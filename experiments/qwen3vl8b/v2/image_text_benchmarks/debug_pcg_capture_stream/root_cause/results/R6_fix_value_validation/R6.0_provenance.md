to a different GPU.

### Amendment A1 (2026-07-28) — R6.1b GPU selection is dynamic

User-authorized amendment before R6.1b execution. R6.1b is **no
longer pinned to GPU 6.** The GPU selection rule for R6.1b is now:

- All GPUs on this host are currently occupied by unrelated
  tenants. We are authorized to use exactly ONE GPU at a time, and
  must never signal, reset, or otherwise interfere with any process
  we did not launch.
- The GPU used for R6.1b is chosen by
  [`scripts/monitor_idle_gpu.py`](../../scripts/monitor_idle_gpu.py)
  — a read-only monitor that polls every 30 s and selects the
  lowest-indexed GPU that satisfies all three idle criteria
  (0 compute PIDs, memory ≤ 500 MiB, utilization ≤ 5 %)
  continuously for at least 600 s. An immediate live recheck runs
  right before hand-off; a failed recheck clears the timer and
  monitoring resumes. Residual memory with no visible process is
  treated as busy.
- The monitor uses a non-blocking `fcntl.flock` on
  `raw/monitor.lock` to prevent two copies from running at once.
- The runner (`run_R6_1_correctness.sh`) continues to require an
  explicit `R6_GPU_ID`; it never selects a GPU itself. The monitor
  passes the selected ID; the runner uses only that GPU.
- The actual selected GPU and its full 10-minute idle-qualification
  interval are recorded in the R6.1 verdict (via
  `raw/monitor_selection.json`, which is loaded and embedded by
  `scripts/R6_1_verdict.py`).
- Historical GPU 6 availability at R6.0 write time is *not* current
  authorization or evidence and does not carry forward.
- `R6.1_correctness/protocol.md` §2 has been amended in the same
  commit as this amendment to reflect the new selection rule.

### Amendment A3 (2026-07-28) — host libcuda LD_PRELOAD pin

User-authorized amendment after R6.1b attempt 01 recorded
`INFRA_FAILURE` (see
[`R6.1_correctness/verdict.md`](R6.1_correctness/verdict.md) and
commit `703ff69`). The failure was initially framed as "driver
silently upgraded" but the root cause has been isolated
experimentally:

- The container ships `cuda-compat-13-0` which puts
  `libcuda.so → libcuda.so.1 → libcuda.so.580.82.07` in
  `/usr/local/cuda-13.0/compat/`. That copy is older than the host
  driver (`595.71.05`) and torch `2.11.0+cu130`'s `cudaGetDeviceCount()`
  fails against it with Error 803.
- With
  `LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libcuda.so.595.71.05`,
  both system python and the profiling conda env successfully
  initialize CUDA and execute a tensor op. Rebuilding conda /
  Docker / torch is not required.
- The confirmed root cause is `compat_libcuda_precedence`, not a
  torch/driver ABI incompatibility.

Environment tuple to record for R6.1b attempt 02 and all
subsequent R6 GPU runs:

| Item | Value |
|---|---|
| NVIDIA driver | `595.71.05` |
| Driver maximum CUDA level | `13.2` (nvidia-smi reports `CUDA Version: 13.0` on this driver build; user recorded max is `13.2`) |
| Container / PyTorch CUDA build | `13.0` |
| torch | `2.11.0+cu130` |
| Required runtime libcuda | `/usr/lib/x86_64-linux-gnu/libcuda.so.595.71.05` (91,501,576 bytes) |
| Compat lib to avoid | `/usr/local/cuda-13.0/compat/libcuda.so.1 → libcuda.so.580.82.07` |
| Runtime env var | `LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libcuda.so.595.71.05` |
| R6 execution GPU | **GPU 2 only** (user-authorized for this attempt; other GPUs may not be silently substituted) |
| Previous failed attempt | commit `703ff69` R6.1b attempt 01 on GPU 1 — historical infrastructure failure only; NOT a clean-Y correctness failure |

Runner + monitor changes made in the same commit as this amendment:

- `scripts/run_R6_1_correctness.sh` prepends the host libcuda to
  `LD_PRELOAD` before any Python invocation, and refuses to run if
  the host lib is missing or empty (exit 65).
- `scripts/R6_preflight_libcuda.py` (new) is called by the runner
  after provenance verification and before any server launch. It
  loads `libcuda.so.1` via `ctypes`, reads `/proc/self/maps`, and
  fails with exit 4 if the resolved path is not exactly
  `/usr/lib/x86_64-linux-gnu/libcuda.so.595.71.05` or is under any
  `/usr/local/cuda-*/compat/` directory. It then imports torch,
  prints driver / torch identity, and runs a minimal CUDA tensor
  smoke on the specified GPU. Failure aborts the runner with exit 65.
- Runner accepts a `R6_ATTEMPT_DIR` env var so a rerun writes into
  a separate directory without overwriting attempt 01's artifacts.
  Default is `attempt_02_host_libcuda_595_gpu2`.
- Runner writes `raw/launch_context.json` (schema companion to
  `monitor_selection.json`) so direct-invocation runs still have
  their launch identity embedded in the verdict.

**Prohibited alternatives** (per user directive):
- Uninstalling `cuda-compat-13-0`.
- Editing `/etc/ld.so.conf.d`.
- Adding `/usr/local/cuda-13.0/compat` to `LD_LIBRARY_PATH`.
- Rebuilding conda or reinstalling torch.
- Rebuilding or recreating the Docker container.
- Rolling back the NVIDIA driver.

### Amendment A2 (2026-07-28) — PGID-scoped cleanup only

User-authorized amendment before R6.1b execution. The R6.1 runner's
cleanup contract is tightened:

- Each server is launched via
  [`scripts/R6_setsid_exec.py`](../../scripts/R6_setsid_exec.py)
  so the launched python process becomes a new session leader
  (PID == PGID == SID). The helper writes its own PID to a
  per-server pidfile before `os.execvp`.
- The runner records `(SRV_PID, SRV_PGID)` after each launch and
  refuses to proceed if `SRV_PGID != SRV_PID` (setsid failure).
- Teardown signals only PGIDs the runner recorded and only after
  re-verifying ownership: `kill -0 <pid>` succeeds, `ps -o pgid=`
  still equals the recorded PGID, and `ps -o comm=` starts with
  `python`. If ownership cannot be re-proven, the runner logs and
  stops — it does not signal.
- The following are **prohibited** anywhere in the R6 tooling:
  `pkill`, `pkill -f`, `killall`, `fuser -k`, kill-by-name,
  kill-by-port without verified PID ownership, and
  `nvidia-smi --gpu-reset`.
- Between servers, the runner checks whether any compute PID on
  the selected GPU has a PGID outside our tracked set. Any foreign
  PID is treated as resource contention: we tear down only our own
  servers gracefully and exit with code 71. The foreign PID is
  never signalled.
- The old `pkill sglang.launch_server` cleanup in the runner has
  been removed in the same commit as this amendment.
